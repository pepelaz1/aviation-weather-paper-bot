# Aviation Weather → PAPER order: Python prototype

Прототип по задаче [Kwork №3274461](https://kwork.ru/projects/3274461/view). Консольное приложение опрашивает METAR API, сравнивает числовое поле с правилами из локального файла и записывает решение об условном лимитном запросе в `bot.log`.

## Быстрый запуск (Windows / Python 3.11+)

```powershell
cd aviation-weather-paper-bot
python weather_bot.py --sample sample-weather.json --once
python -m unittest -v
```

Для теста на текущую дату замените дату первой строки `rules.txt` на сегодняшнюю. Пример котировки `price=0.42`, `available_size=12` встроен в код как **заглушка**: API второго сервиса и его клиент заказчик ещё не указал. В `bot.log` будут время проверки, значение, котировка, доступный объём и результат PAPER. Исходный файл `.env.example` можно скопировать в `.env`, если нужно поменять режим и часовой пояс.

## Что реализовано

- Четыре настраиваемые группы запросов в `config.json`: минуты часа, длительность окна, интервал внутри окна.
- Часовой пояс через `zoneinfo`; повторное чтение `rules.txt` раз в 30 секунд, с сохранением последних корректных правил при ошибке.
- Чтение METAR JSON по станции, проверка порога, защита от повторной обработки одной и той же сводки.
- Ограничение частоты обращений к погодному API, таймаут и безопасная обработка ошибок/пустых ответов.
- PAPER режим с записью условного лимитного запроса; остановка по Ctrl+C.

Формат правила: `YYYY-MM-DD, оператор, погодное значение, максимальная котировка, максимальный объём`. Операторы: `>=`, `>`, `<=`, `<`, `==`.

## Границы прототипа

Режим `LIVE` намеренно блокируется: описание заказа не содержит названия второго API, схемы подписи, полей заявки и тестового стенда. Код **не отправляет реальные заявки**. Для полной версии нужны документация официального клиента, точные минуты четырёх групп, значение и единицы погодного поля, формат правил, часовой пояс, порядок повторов и реакция на ошибки. При повторном запуске история уже обработанных наблюдений в памяти не сохраняется; в рабочей версии нужен постоянный журнал состояний.

Погодный API просит ограничивать нагрузку: максимум **100 запросов в минуту**, с учётом частоты обновления сводок. Примерный график консервативный: четырежды в час по 12 секунд с шагом 2 секунды. Реальный график следует согласовать с заказчиком и ограничениями сервиса. [Официальная документация AviationWeather](https://aviationweather.gov/data/api/).

## Состав

`weather_bot.py` — приложение; `config.json` — график и поле; `rules.txt` — пороги; `sample-weather.json` — офлайн-сводка; `test_weather_bot.py` — проверки без сети и реальных заявок.
